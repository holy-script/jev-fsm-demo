# 05. v3 "Posture Duel" (REAPER'S DANCE)

The main product. A Sekiro-inspired duel game: top-down movement with side-view sprites, posture bars, deflects, perilous attacks, deathblows, a tutorial, a skill shrine, three areas, five encounters ending in a final boss, music-synced choreography, and Jev choosing the enemy's actions. Route `/duel`.

This document is the architecture reference. Companion docs: Jev side in [02](02-jev-integration.md), assets in [06](06-asset-pipeline.md), tests in [07](07-testing.md), recipes in [08](08-extending.md).

## 1. The player experience (so you know what you are changing)

1. Title screen (Continue / New Game / Settings / Jev vs Rules / Credits). New games start with a **tutorial** in the Monastery courtyard: the Instructor (a translucent blue echo of the hero) teaches 12 lessons against the invincible **Sparring Shade**.
2. The gate opens. Encounters in order: **Bone Soldier** and **Spear Bearer** (grunts, rules brain, Hall of Spears), **Skeleton Captain** (boss 1, courtyard arena), travel to **the Foundry**: **Mecha-Stone Golem** (boss 2), travel to **the Summit**: **Bringer of Death** (final boss, three lives).
3. Between bosses: a **shrine** (spend skill points, 1 earned per boss, 2 at start), story lines, area title cards, lighting (areas are dark; braziers, shrines and the player carry light).
4. Fights are choreographed to the music in "Choreographed" timing, or use the original uneven timing in "Classic" (a setting).
5. The boss's decisions come from Jev; `F` swaps to the rules bot; `Tab` shows the decision log.

Keys: WASD/arrows move, `J` light chain (slash, slash, thrust), `K` heavy, `Space` or right mouse guard (tap just before impact = deflect, hold = block), `Shift` roll, `E` kick, `Q` heal, `L` whirl cut, `I` throwing blade, `Enter` interact/advance dialogue, `Esc` pause, `R` retry, `M` music, `F` brain, `Tab` Jev panel. Dev keys: `Z X C V B` force the boss's moves (dummy mode), `G` guard, `N` auto toggle, `T` refill, `Y` wake, `1`/`2` pick the Captain/Golem (the Bringer: `__duel.reset(__duel.idxOf("bringer"))`).

## 2. Architecture at a glance

```
createDuelGame.ts   Phaser.Game (1280x720, FIT). BootScene loads manifest.json -> sheets, tiles, maps, audio, music.
                    Scenes: boot, duel (DuelScene), duelhud (HudScene), menu (MenuScene), skills (SkillScene).
                    Exposes window.__game outside production. Registry: hooks (React callbacks), dev (bool).
DuelScene.ts        The simulation. One class, ~2400 lines, sections in the order below.
HudScene.ts         Overlay scene: reads DuelScene.hud (a plain object each frame) and draws bars, prompts, dialogue, cards.
MenuScene.ts        Title + pause + settings + credits + Jev-vs-Rules stats (one scene, two modes).
SkillScene.ts       Shrine UI.
data.ts             Every content table. Pure data and types; no Phaser.
brain.ts            Telemetry, prompts, Jev calls, rules brain. No Phaser.
engine.ts           World (tiles/objects/collision) and Fighter (sprite wrapper), geometry helpers.
sfx.ts / vfx.ts     Audio and visual effects engines.
skills.ts, tutorial.ts, settings.ts
```

Data flow per frame: `DuelScene.update(now, deltaMs)` -> clears the `fx` graphics -> copies state into `this.hud` -> picks one of four update branches (hit-stop, travelling, dialogue, normal) -> inside normal: `updatePlayer`, boss telemetry sampling, `updateBoss`, projectiles, beams, pillars, taunt, blades, separation, `checkWake`, tutorial waiters -> then camera, NPC, zone/title cards, lighting, fx draw. React gets events only through `hooks` (`onDecision`, `onLog`, `onMissingAssets`).

The view is 1280x720 with the camera at zoom 2 (so 640x360 world pixels visible). While the boss is awake the camera is bounded to the arena rect (`world.arena`), which is how a large map "focuses on a region".

## 3. The world

### Maps
Tiled JSON, 16 px tiles, generated by `tools/make_duel_map.py` (not hand-drawn) into `public/maps/duel_arena.json` (Monastery, 80x60 tiles), `foundry.json`, `summit.json`. Tile layers: `ground` (floor; gid 0 means void = blocked) and `walls`. The plateau face row (gids 15 to 18) is blocked so the cliff edge reads as an edge. Object layer `objects` with typed objects:

| type | name | meaning |
|---|---|---|
| `spawn` | `player`, `boss`, `shade`, `npc` | start positions (feet) |
| `gate` | | a 12-tile-wide opening that is solid while `world.gateOpen` is false |
| `arena` | | rectangle that locks the camera and limits the boss fight |
| `light` | | properties `radius`, `color` (hex): a brazier/light source |
| `shrine` | `id` | rest point (heals, refills, opens the skill screen) |
| `lore` | | property `text`: an inscription |

`World` (engine.ts) parses these into `spawns`, `gate`, `lights`, `shrines`, `lore`, `arena`, and exposes `blocked(rect)` (footprint rectangle against ground void, face tiles, walls, closed gate).

### Areas (`AREAS` in data.ts)
`AreaDef`: id, display name, map key, ground and wall tints, background colour, `ambient {alpha, color}` (how dark), `music`, optional `stars`, and `zones` (title-card regions by tile row). Areas: `monastery` (zones Hall of Spears and Courtyard), `foundry`, `summit` (starfield). Each `BossDef.area` says where it is fought; `areaFor(def)` returns it, except in dev mode where everything is in the Monastery.

`loadArea(id)` builds the tilemap layers with tints, sets camera background and bounds, creates stars if needed, then `buildProps`. `travel(idx)` fades out (700 ms), `reset(idx)` (which loads the area if it changed), fades in (900 ms), shows the area card, and may speak an Instructor briefing.

### Lighting
Only when `lightsOn` (always in the real game; opt-in in dev with `?light=1` because software rendering is slow). `buildProps` makes a RenderTexture over the map plus a generated radial `lightmask` texture. Every frame `drawWorldLight` clears it, fills with the area ambient, and **erases** soft circles for lights, shrines, the player (radius 215) and the awake boss (130); additive tinted glow sprites flicker above. Braziers, shrine pedestals and lore slabs are drawn into `propsGfx`.

### Interaction
`updateNearby` finds a shrine (reach 34) or lore slab (reach 30) when no dialogue, travel, tutorial or fight is active; a prompt text follows. `interact()` (Enter): lore -> `say("INSCRIPTION", ...)`; shrine -> `rest()`: full heal, refill gourd, refill spirit, save, and open the skills screen.

## 4. Characters

`Fighter` wraps a Phaser sprite: `(x, y)` is the point between the feet; a small footprint box does collision via `move(world, dx, dy)` (axis-separated so you slide along walls). It plays animations named `<prefix>_<suffix>` (`hero_idle`, `cap_atkA`, `bod_cast`...). `nativeDir` says which way the art faces (Bringer faces left: `-1`) so `face` flips correctly. `anchorX` overrides the torso centre when a weapon skews the sprite bounding box (the grunts, the Bringer). Helpers: `play`, `freeze`, `hitFlash`, `tickFx`, `sync`.

Animation **suffix names** used by moves and `BossDef.anims`: `idle walk atkA atkB hit block dead jump` plus boss-specific (`melee arm laser armor` for the Golem, `cast` for the Bringer).

## 5. The player controller (`updatePlayer`)

Modes (`PMode`): `free guard attack kick roll heal hurt broken dead`. The player always **faces the boss** while one is awake (locked facing; this is a duel game).

Key constants (`HERO` in data.ts): 100 HP, 100 posture max, speed 95 (42 while guarding), roll speed 170 for 420 ms with i-frames from 40 to 340 ms and 160 ms cooldown, 3 heals of 45 HP taking 1000 ms, posture regen 22/s after 1100 ms (half while guarding), broken for 1700 ms then posture 45, chip damage through a block 12%.

Inputs are **buffered** (`atkBuf`, `heavyBuf`, `rollBuf`, `kickBuf`, `healBuf`, `artBuf`, `toolBuf`) so presses during recovery of another action still register shortly after.

- **Guard.** Pressing starts the deflect window (`GAME.deflectMs` 160 by default; difficulty Assist 220 / Shadow 130; Keen Eye +40). Guard-spamming gets no window: pressing again within `deflectSpamMs` (260) of the last press sets `noDeflect`.
- **Deflect** (guard pressed within the window before impact): no damage, boss gains the hit's `deflectPosture` (x1.3 with Iron Wrist), the player gains spirit (+1, +2 with Echo), a **riposte window** opens (800 ms; `SPIRIT.riposteMs`).
- **Block** (guard held, outside the window): chip damage, the player's posture rises by the hit's `posture`.
- **Roll.** I-frames avoid anything except a grab. Rolling **into** a thrust at the right moment is a **slip**: boss flinches 700 ms, gains +30 posture, player gains spirit and a longer riposte (1100 ms).
- **Attacks** are `MoveDef`s in `HERO_MOVES` (light A, C, B chain in `LIGHT_CHAIN`; heavy D; KICK; RIPOSTE; ROLLCUT; WHIRL; THROW) with hit frames, damage, posture, shapes (cone or circle) and lunges. **Whirl** (L, 2 spirit) hits all around and breaks a raised guard; **throwing blade** (I, 1 spirit) is a ranged posture chip. **Kick** breaks a raised guard.
- **Heal** (Q) takes 1 s (0.7 s with Quick Gourd), the player can creep slowly meanwhile, and being hit cancels it with no HP restored. Healing is limited to 3 gourd charges per fight (a boss kill refunds one; shrines refill).

Telemetry hooks sit at: guard press, attack start, roll start (with direction relative to the boss), heal, deflect, hurt.

## 6. The combat model

### Posture
Both sides have posture 0..100. The player's rises from blocks and from being hit (40% of the hit's posture value); full = `broken` (1.5x damage taken, 1.7 s). The boss's rises from deflects, riposte hits, heavy hits, kicks on guards, slips, reflected projectiles and blocked light hits (30%). **Boss posture at 100 breaks it** (`checkBossBreak`, also called every frame as a safety net): 3.4 s of `broken` in which any real strike is a **deathblow**. The bar reads full for the whole stagger. Boss posture slowly regenerates (14/s, after 1.8 s without a hit, slower when its health is low).

### Health, segments, deathblows
A boss has `segments` lives of `segmentHp`. When a segment's HP reaches 0 and it is not the last, it breaks for 5 s (`segmentEmpty`, "STRIKE: DEATHBLOW" cue) and only a deathblow ends the segment: `deathblow()` advances `b.seg`, refills HP, resets posture, flinches 1.3 s. The last segment dies on HP 0 (`killBoss`). Phase 2 is `seg >= 1`: bosses get `mul()` (1.12 anim speed, 0.8 holds and cooldowns, 1.15 speed), some moves have phase-2 variants (`spawnsP2`, gate options with `phase2`, 0.5 beats shorter lead).

### Attack types (`AtkType`)
`normal`, `heavy` (blockable/deflectable), `thrust` (unblockable; roll into it to slip), `sweep` (unblockable; roll through it), `grab` (ignores guard **and** i-frames; only distance saves you), `beam` (unblockable). Warning **glyphs** (`GLYPH`) mark the unblockable ones above the boss in colour (thrust red, sweep yellow, grab purple, beam orange) with a distinct warning sound (`sfx.warn(type)`).

### Resolving a boss hit (`resolveBossHit`)
Each `HitDef` has an animation frame window `[a,b]`. Each frame in the window the shape (cone or circle around the boss's aim direction) is tested against the player. Order: out of range -> nothing; roll i-frames and not a grab -> `dodged` (and a thrust while rolling = slip); a grab -> `hurtPlayer(grab)`; guard up and the hit is normal/heavy -> deflect if inside the window else block; otherwise a hit. Outcomes are recorded per move for Jev (`deflected blocked dodged slipped hit missed`).

### Resolving a player hit (`playerHitsBoss`)
Boss `broken` -> deathblow. Boss guarding: stone guard (Golem) shrugs everything except the heavy `D`, which breaks it; a normal guard is broken by kick/whirl; light hits just chip posture. Otherwise damage (halved when armored) times difficulty `dealt`, posture, flash, VFX, flinch with a **poise window** (1.1 s after a flinch no new flinch, so spamming lights cannot stunlock). `noFlinch` bosses only flash/squash.

### Difficulty (`DIFFICULTY`)
Assist (deal x1.3, receive x0.65, deflect 220 ms), Duelist (1/1/160, intended), Shadow (0.9/1.3/130).

## 7. The boss runner

### Mode machine (`BMode`)
`idle move attack recover guard flinch broken dead`. `updateBoss` per frame:
- Safety: `checkBossBreak`, `watchdog` (cuts any state held far past its natural length: attack 9 s, broken 8 s, idle 4.5 s, others 6 s; skipped in training, dialogue, story holds, travel, when auto is off).
- Posture regen; tint management (armor = cyan tint).
- `idle`: ask Jev (`ensureRequest`) and consume the answer (`takeDecision`). `move`: walk (approach/backstep/circle) while prefetching the next answer. `recover`: stand, prefetch; in choreographed mode take a small fencing step back after a string. `guard`: hold the guard pose (Golem stone guard lasts 2.2 s). `flinch`/`broken`: timers.
- `attack`: `runBossMove`.

### Actions
Generic actions every boss has: `APPROACH` (walk to within 64 px, 1 s), `BACKSTEP` (520 ms, only if space behind), `CIRCLE` (850 ms), `WAIT` (a beat, or 450-750 ms), `GUARD` (5 s cooldown). Plus the boss's own moves. `availableActions(now)` computes the legal set: not on cooldown, within `reach * 1.3`, buff not already active, GUARD off cooldown, and the **fairness cap** (no third unblockable in a row).

### Anatomy of a move (`MoveDef`, data.ts)
```
id, label, desc (shown to Jev), reach, cooldown (default 1500; scaled in phase 2),
kind: melee (default) | projectile | beam | buff | pillars | blink,
anim (sheet suffix), fps,
hits[]: { frames:[a,b], type, damage, posture, deflectPosture, shape }
holds[]: { frame, ms, telegraph? }  freeze on a frame: the wind-up; telegraph:false = fixed pause
leadBeats, gapBeats[], grid           choreography: beats to first impact, beats between impacts, snap grid (1 = on the beat, 0.5 = syncopated)
lunge[]: { frames, speed }            forward step during frames
gates[]: GateDef                      combo branch points Jev decides
endFrame                              end the animation early
spawns / spawnsP2 / beam / buff / pillars / blink   per-kind payloads
```
`runBossMove` is the interpreter: handles holds (and gate waits), aims (the facing/aim tracks the player until the first hit frame, or until `lockMs` before a beam fires), lunges (with afterimages), kind effects (`runMoveEffects`), hit resolution, gate requests, and the end-of-move recovery.

### Move kinds
| Kind | Mechanism |
|---|---|
| melee | `hits[]` resolved against the player's position |
| projectile | `spawns[]` fire a sprite (`fx_fist`, tinted purple for the Bringer); the player can block it, roll through, or **deflect it back** (it reverses at 1.25x speed and hurts the boss's posture) |
| beam | at `beam.frame` a rotated beam sprite with a length and half-width, active `ms`; aim locks `lockMs` before firing; counts as unblockable |
| buff | armor: 7 s of half damage taken, partial posture immunity, no flinch, +25% damage dealt |
| pillars | at `pillars.frame` marks `count[seg]` circles under/around the player; a swelling telegraph ring; after `delayMs` they strike (unblockable, dodge by rolling or leaving) |
| blink | at `blink.frame` the boss fades and reappears 60 px behind the player 300 ms later |

### Choreography (beat mode)
`planHolds(mv, now, rhythm)` converts each telegraph hold into a duration so the impact lands on the music's beat grid: it reads `sfx.beatPos()` (fractional beats since the track started), computes where the first impact would naturally fall, and extends the hold so it snaps to the next multiple of `grid` beats after `leadBeats` (never shorter than the animation allows, +90 ms margin). Later impacts use `gapBeats`. Jev's optional `rhythm` shifts the plan: `OFF_BEAT` adds half a beat, `SLOW` one beat, `QUICK` removes one (floor of 1). Recoveries and the post-string fencing step are also measured in beats. `settings.beat === "classic"` skips all of this and uses raw `ms` holds. The tutorial Shade always forces classic timing.

### Gates (combos Jev can branch)
`GateDef { after, at, options, default }`: once hit index `after` has resolved, Jev is asked how the combo continues; the answer applies at `at` (a frame, or `"end"`). Standard options: `CONTINUE`, `DELAY` (hold half a beat longer), `FEINT` (cancel into guard), `END`, or a move id to chain (filtered by cooldown). While waiting, the boss stays poised on the frame for up to `GATE_WAIT`; no answer means the default.

### Jev decision plumbing (summary; full detail in 02)
`ensureRequest` (prefetch, rules or Jev), `setDecision` (logs, shows probabilities, speaks the taunt), `takeDecision` (stale/unavailable handling, **intent** for out-of-reach picks, ASK_TIMEOUT fallback, rhythm hand-off), `execAction`, `forceMove(id)` (sets up a move: hit arrays, gate runtime, plan, cooldown, history, anim, glyph and warning sound).

## 9. Tutorial (`tutorial.ts` + host in DuelScene)

`runTutorial(host)` is an async script. The scene implements `TutorialHost` (`say`, `objective`, `count`, `resetCounts`, `until(cond, {progress, hints, timeoutMs})`, `shade.{loop, stop, guardLoop, speed}`, `ringAid`, `player.{setHp, giveHeals, fill, giveSpirit}`, `openShrine`, `finish`, `moved`). Each lesson: Instructor line(s), an objective on the HUD panel, the Shade's demonstration (`shade.loop([moves], gapMs)`), wait until a condition counted from game events (`tutEvent(name)` bumps `cnt[name]`; `outcome()` also emits `<MOVE>:<result>` events), with escalating hints on a timer. Lessons: MOVE, STRIKE, BLOCK, DEFLECT (with a timing ring that closes at impact), RIPOSTE, SWEEP, SLIP, GRAB, DEATHBLOW, KICK, HEAL, shrine + optional skill lessons (Roll Cut, Whirl Cut, Blades if bought), THE TEST (Shade at full speed). The tutorial forces classic timing and freezes mercy: player HP never below 20 against the Shade. `skipTutorial()` (pause menu) cancels the script (`tutCancelled`; tutorial `say`/`until` reject), then `finishTutorial()`. Finishing opens the gate, saves `tutorialDone`, fades the Shade, spawns the first grunt.

## 10. Skills, spirit, shrine

`skills.ts`: nine skills in three paths (Deflection: Keen Eye, Echo, Iron Wrist; Flow: Roll Cut, Whirl Cut, Riposte Reach; Tools: Throwing Blades, Spirit Well, Quick Gourd). `has/canBuy/buy/awardPoint`; costs mostly 1 (Whirl Cut 2); Echo needs Keen Eye. Start with 2 points, +1 per boss: you cannot buy everything. **Spirit** (base 3, +2 Well) is earned by deflects and slips and spent on Whirl (2) and Blades (1). The shrine UI is `SkillScene`, reachable after each boss, by resting at a shrine, and from the pause menu.

## 11. Story, dialogue, taunts

- **Dialogue**: `say(who, lines, story=false)` returns a Promise; the HUD shows a typewriter box; Enter completes then advances. While a dialogue is up the world is frozen (the dialogue branch of `update`). Tutorial lines are cancellable by skip; **story lines pass `story=true` and always play**.
- **Intro/outro/briefing**: `BossDef.intro` plays on `wake()` (the boss holds, `storyHold`), `outro` as it falls, `briefing` (Instructor) on arriving in a new area. Each is shown once per save (`save.seen` keys `intro:<id>`, `outro:<id>`, `brief:<id>`). Dev mode skips all story so tests are unaffected. After the final outro a "THE DANCE ENDS" card appears.
- **Inscriptions**: lore objects, read with Enter.
- **Taunts**: `BossDef.taunts` is a list `{id, text, when}` given to Jev as the optional `taunt` question; the chosen line floats above the boss for 3.2 s, with a 14 s cooldown.

## 12. Audio (`sfx.ts`)

Everything runs through one compressor bus (a Web Audio `DynamicsCompressor` and a master gain driven by the sound volume setting). Two sources: 20 recorded CC0 sword sounds (`clash1..10`, `blade1..10`, loudness-normalised to wav by the asset script) and **synthesised cues** built from oscillators and noise with per-cue dB trims. Semantic cues used by game code: `swing`, `hit`, `deflect`, `block`, `clash`, `clang`, `stoneHit`, `guardBreak`, `slip`, `postureBreak`, `deathblow`, `hurt`, `roll`, `heal`, `throwFist`, `buff`, `charge`, `beamFire`, `warn(thrust|sweep|grab|beam)`, `blip(who)` (typewriter), `riposteReady`, `spirit`, `whirl`, `throwBlade`, `bladeHit`, `locked`, `skill`. Music: `playMusic(key, volume)` / `stopMusic` / `toggleMusic`, five tracks (temple, castle, captain, crypt, final) with **measured** tempo and phase from `tools/bpm.py`; `beatPos()` returns the fractional beat position of the playing track, which choreography uses. Because the author cannot listen, levels were set by measuring offline renderings (`tests/duel/audio.mjs` prints peak and loudness per cue).

## 13. Visual effects (`vfx.ts`)

Where an animation is missing, effects stand in. Tintable white-on-transparent sheets (hit sparks, impact, break, blood, shards, splash, smoke, heal) are tinted at spawn; helpers: `hit`, `deflect`, `blockSplash`, `postureBreak`, `deathblow`, `shock`, `shards`, `blood`, `dust`, `afterimage(fighter, tint, alpha, ms)`, `squash(fighter, sx, sy, ms)`. Hurt = red body flash plus blood; heal = green pulse and sparkle; unblockable lunges leave tinted afterimages. The scene also draws cone/circle telegraph shapes, timing rings (tutorial) and pillar markers into the `fx` Graphics each frame.

## 14. HUD, menus, React shell

- `HudScene` reads `DuelScene.hud` (`HudState`: bars, boss info, spirit pips, riposte prompt, dialogue, objective, card, brain label, message/sub banner, last decision). It never mutates the game.
- `MenuScene`: title (with embers), pause, settings (Combat timing, Difficulty, Music, Sound volume), credits, **Jev vs Rules** stats computed from `save.runs`.
- `DuelClient.tsx`: the canvas fills the window; `Tab` toggles an overlay with the decision log (action, probability, source, latency), the reads gauges, and the key legend.

## 15. Persistence (`settings.ts`)

`localStorage` keys, both merged over defaults and wrapped in try/catch:
- `duel.settings`: `{beat, difficulty, music, sfx}`.
- `duel.save`: `{cleared[], deaths, skills[], points, tutorialDone, seen[], memory{bossId: BossMemory}, runs[RunRecord]}`. `resetSave()` is New Game. Old saves missing newer fields are handled with `??=`.
`BossMemory` and `RunRecord` are described in [02](02-jev-integration.md) (memory) and the stats screen.

## 16. Test hooks

Outside production the scene is `window.__duel` and the game `window.__game`; the registry flag `dev` is set by `?dev=1`. Tests call private methods directly (TypeScript privacy is not enforced at runtime): `reset`, `debugWake`, `forceMove`, `startMove`, `tutEvent`, `snapshot`, `planHolds`, `availableActions`, `takeDecision`, `remember`, etc. Keep these method names stable or update `tests/duel/` with them.

## 17. Frame-order cheat sheet

`update`: fx clear -> hud sync -> [hit-stop | travelling | dialogue | normal(updatePlayer -> telemetry -> updateBoss -> projectiles -> beams -> pillars -> taunt -> blades -> separate -> checkWake -> tutorial waiters)] -> movement distance counter (ignores jumps > 40 px) -> NPC -> zone/prompt -> lighting -> fighter fx -> camera -> fx draw. Hit-stop pauses animation by setting `anims.timeScale = 0` for a few frames; scene time keeps running.

## 18. Things that are deliberately simple

No pathfinding (bosses walk straight at you and stop if blocked; arenas are open). No networking. No save slots. No gamepad. No per-frame hitbox data (cones/circles by move). Telegraphs are glyph + sound + pose; there is no screen-edge arrow.
